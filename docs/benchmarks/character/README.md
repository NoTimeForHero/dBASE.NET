# Чтение текстовых полей C

19 ноября 2026 года. База сравнения — `8a9110ddc0e768d80601c79df47d8b796a1dcd4f`. В системных неизменяемых кодировках CP866, CP1251, ASCII и UTF-8 с подходящим обработчиком неверных байтов обычные пробелы убираются до декодирования. Строковый `Trim()` по-прежнему обрабатывает остальные пробельные символы. Для пользовательских кодировок и строгого UTF-8 декодеру передаётся исходный диапазон байтов. [Декодер](../../../dBASE.NET/Encoders/CharacterEncoder.cs#L43)

## Условия и результаты

Обе версии собраны в Release и запущены последовательно со стендом BenchmarkDotNet 0.15.8 для `net472` под .NET Framework 4.8.1 (4.8.9310.0), x64. Использовалась та же пара Harbour DBF/FPT на 10 000 физических записей, что и в исходном замере. SHA-256 файлов совпали с базой. Исходник стенда совпал для обеих сборок. Один запуск, три итерации прогрева и восемь измерительных с целью 200 мс. [Базовые условия](../efb9651/README.md), [сценарий чтения двух полей](../../../dBASE.NET.Tests/benchmarks/Harbour/HarbourReadBenchmarks.cs#L108)

Время приведено как среднее ± `Error` BenchmarkDotNet за проход по 10 000 строкам.

| Сценарий | Время до → после, мс | Ускорение | Аллокации до → после, байт/строку |
| --- | ---: | ---: | ---: |
| Полные записи, блоками | 12,492 ± 0,322 → 11,193 ± 0,191 | 1,12× | 1 281,56 → 1 032,82 |
| `FULL_NAME` и `HOUSE_NO`, блоками | 2,674 ± 0,052 → 1,634 ± 0,023 | 1,64× | 383,70 → 134,98 |

Прошли все 107 обнаруженных тестов, включая сверку с эталоном Harbour. В новых тестах проверены пустые поля, пробелы Unicode, внутренние пробелы и нулевые символы, ненулевое смещение, пользовательская кодировка и позиция ошибки строгого UTF-8.
