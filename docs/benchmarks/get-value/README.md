# Повторное использование буфера в FastDbf.GetValue

Замер от 19 ноября 2026 года. Исходник библиотеки — `67c683a7d1d7656576b7781f27b12f9237189b41`. В оптимизированной сборке `GetValue` переиспользует выделенный при первом обращении буфер для поддерживаемых полей в файлах, открытых только для чтения со штатной неизменяемой кодировкой. Декодеру передаётся фактическое число прочитанных байтов. Memo, неизвестные типы, пользовательские кодировки и переданные извне потоки продолжают использовать исходный путь. [Код](../../../dBASE.NET/FastDbf.cs)

Обе DLL собраны в Release с целью `net8.0` через SDK 10.0.404. SHA-256 исходной DLL — `4880efe4125e05f34c39d6eca81ecb285255ec2c6ab53cfc9c675703f62e2a05`, оптимизированной — `873f3e80028bc535b85136367e908497c83c7f68828c51400a34d432e8ed2f56`. BenchmarkDotNet 0.15.8 запускал отдельные процессы на .NET 10.0.15 (10.0.1526.53008) и .NET 8.0.0 (8.0.23.53103), x64 RyuJIT. Машина Intel Core i7-12700K, Windows 10 22H2 (19045.6456). По одному запуску, три итерации прогрева, восемь измерений по 200 мс. Файловый кэш прогрет.

Использовались те же 10 000 строк Harbour с CP866. DBF — 1 690 451 байт, SHA-256 `3173b2d9ecc60dfd66af17de37f265e6467136207ca8fa2dbe0db9f1ff1770b5`. FPT SHA-256 — `1fa8e8dcff0963072702b125cf12b20cb9ae5af14b3934e9dedeb8a3e1e35326`. Сценарии `SequentialGetValue` и `RandomGetValue` читают `ID` и `IS_PRINTED` у каждой строки, случайный порядок задаётся начальным значением 866. `SequentialGetMemo` и `BlockReadValues` служат контролем. [Данные](../efb9651/README.md), [стенд](../../../dBASE.NET.Tests/benchmarks/Harbour/HarbourReadBenchmarks.cs)

На обоих рантаймах обе сборки прошли `--verify` на контрольной таблице из 1 000 строк до первого замера. Проверены значения всех полей, флаги удаления, чередование сканирования с индексными чтениями, владение прочитанными значениями и корректность чтения после усечения отдельной копии DBF.

## Воспроизведение

Из корня репозитория собрать один и тот же стенд со ссылкой на каждую версию библиотеки. Для исходной версии использовать изолированную копию исходников и другое имя проекта стенда. Затем для каждой DLL и цели стенда выполнить следующие команды. Для `--verify` подставить фактический рантайм 8.0.0 или 10.0.15.

```powershell
dotnet build $project -c Release -f net8.0
dotnet exec --fx-version $runtimeVersion $benchDll $smokeFixture --verify
dotnet $benchDll $fixture --runtimes $target --filter '*.SequentialGetValue' '*.RandomGetValue' '*.SequentialGetMemo' '*.BlockReadValues' --launchCount 1 --warmupCount 3 --iterationCount 8 --iterationTime 200 --artifacts $artifacts
```
