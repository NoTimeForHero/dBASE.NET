# Чтение memo через ReadValues без сохранения указателя

Замер от 19 ноября 2026 года. Исходник `03ad4a6d8bc22b186d1a547946d7e0efffc4b467`. `ReadValues` выбирает декодер, который разбирает указатель прямо из диапазона поля и не добавляет состояние записи в `EncoderContext`. Четырёхбайтовый указатель читается по смещению, текстовый декодируется с прежними правилами, а укороченный бинарный указатель сохраняет прежнюю ошибку. Записываемые `DbfRecord` продолжают хранить собственную копию указателя. [Декодер](../../../dBASE.NET/Encoders/MemoEncoder.cs), [выбор декодера](../../../dBASE.NET/Encoders/DbfReadColumn.cs)

У обеих DLL цель `net8.0`, Release, SDK 10.0.404. SHA-256 исходной DLL — `63a9ef92c7ef95accc6a59c3c26a5924b7011ea4f73d7b690e79208bd3dccff4`, изменённой — `9493db8a0db26dae9ca216430d57b0eb988028306c4a5ba026e2c9d5eb99bc92`. BenchmarkDotNet 0.15.8, фактические рантаймы .NET 10.0.15 и .NET 8.0.0 x64. Окружение, CP866, размеры и хеши Harbour DBF/FPT, прогрев и параметры замеров совпадают с этапом `GetValue`. [Условия](../get-value/README.md)

Для DBT использовались 10 000 обращений к трём строкам, включая длинное memo в 1 404 символа. DBF — 396 байт, SHA-256 `05dcf2feb2d32bc35a99287d5b2262e55432c245082e7ad3e4c593848acb30bf`. DBT — 7 186 байт, SHA-256 `a05085161e2479538fa340bd8839121566471faa575a33ec1147dc47210c1d69`. Проекция многократно перечисляет короткую таблицу, поэтому её абсолютное время не сравнивается с FPT. [Сценарии DBT](../../../dBASE.NET.Tests/benchmarks/Harbour/DbtMemoBenchmarks.cs)

Сверки FPT и DBT `--verify` прошли до замеров на обеих сборках и обоих рантаймах. В наборе MSTest прошли все 109 тестов, включая запись сохранённых memo и сравнение с Harbour.

Проекция FPT на обоих рантаймах выделяет 72 байта на строку меньше. Время чтения только memo снизилось на 22% на .NET 10 и на 20% на .NET 8. Полная проекция выделяет столько же байтов меньше на строку, а интервалы времени пересекаются. Для DBT проекция экономит около 84 байт на обращение. В окончательной серии индексный контроль DBT имеет одинаковые аллокации и пересекающиеся интервалы времени.

Вариант с общей реализацией декодера изменял разбор указателя и в индексном пути. Два прогона на .NET 8 показали рост его среднего времени с 9,160 до 9,938 мс и с 9,155 до 9,689 мс. Его заменили отдельным декодером, который выбирает только `ReadValues`.
