# Чтение memo из FPT и DBT

База сравнения — `0051821821c932bed1669a4bdd1ce015478d4a1a`. FPT читает четырёхбайтовую длину без временного массива и переиспользует буфер размером до 64 КиБ для системных неизменяемых кодировок. При коротком содержимом в конце файла декодируются доступные байты. Неполный заголовок длины теперь даёт `EndOfStreamException` от `BinaryReader`. DBT читает содержимое блоками за один проход, находит пару `0x1A` на стыке блоков и сообщает об отсутствующем терминаторе. Пользовательским кодировкам передаётся отдельный массив фактической длины. [FPT](../../../dBASE.NET/Memo/Adapters/FoxProAdapter.cs) · [DBT](../../../dBASE.NET/Memo/Adapters/Dbase3Adapter.cs)

`FastDbf.ReadValues` уже обращается к содержимому memo только при выборе соответствующего столбца. `FastDbf` в режиме `readOnly: true` читает исходный sidecar по мере обращений. `Dbf.Read` сохраняет локальную копию memo для последующего редактирования и записи. [Выбор столбцов](../../../dBASE.NET/FastDbf.cs#L141) · [Копирование memo](../../../dBASE.NET/Dbf.cs#L110)

## Условия и результаты

BenchmarkDotNet 0.15.8, Release, цель `net472`, .NET Framework 4.8.1 (4.8.9310.0), Windows x64. До и после использованы побайтно одинаковые исходники стенда. Каждый сценарий запускался один раз с тремя итерациями прогрева и восемью измерительными с целью 200 мс. Для FPT использована исходная пара Harbour на 10 000 записей с 2 857 непустыми memo. Для DBT выполнено 10 000 точечных чтений с циклическим обходом существующей тестовой таблицы `large.dbf`, включая значение длиной 1 404 символа. Оба варианта читали одни и те же файлы. [Базовая пара файлов](../efb9651/README.md) · [Стенд DBT](../../../dBASE.NET.Tests/benchmarks/Harbour/DbtMemoBenchmarks.cs)

| Сценарий | Время до → после, мс | Коэффициент | Аллокации до → после, байт на строку или чтение |
| --- | ---: | ---: | ---: |
| FPT, полные записи блоками | 11,734 ± 0,445 → 11,327 ± 0,649 | 1,04× | 1 032,83 → 1 012,19 |
| FPT, столбец `NOTE` через `GetValue` | 12,632 ± 0,178 → 12,495 ± 0,532 | 1,01× | 167,68 → 147,07 |
| FPT, столбец `NOTE` блоками | 4,156 ± 0,186 → 4,084 ± 0,156 | 1,02× | 206,40 → 185,78 |
| DBT, столбец memo через `GetValue` | 45,939 ± 1,547 → 32,922 ± 1,124 | 1,40× | 630,19 → 463,13 |

Для FPT интервалы времени пересекаются. Аллокации снизились во всех сценариях FPT примерно на 20,6 байта на строку. BenchmarkDotNet исключил по одному выбросу в трёх сценариях FPT после изменения. В DBT среднее время уменьшилось на 28%, аллокации — на 27%.
