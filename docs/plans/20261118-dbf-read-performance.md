# План ускорения чтения DBF в dBASE.NET

Дата исследования — 18 ноября 2026 года.

План основан на статическом анализе рабочей копии форка на базе `0711bc7`. В ней уже есть изменения для открытия файлов только для чтения, подключения FPT по схеме и декодирования Harbour `@` и `=`. Базовый замер следует сделать на зафиксированной версии после сверки этих исправлений с Harbour. Приведённый порядок отражает ожидаемую пользу по коду. В рамках исследования замеры не проводились. [План совместимости с Harbour](20261118-harbour-fastdbf.md#2-эталон-чтения-в-harbour), [открытие FastDbf](../../dBASE.NET/FastDbf.cs#L33), [выбор декодеров](../../dBASE.NET/Encoders/EncoderFactory.cs)

## Порядок замеров на .NET Framework 4.7.2

Стенд Harbour на BenchmarkDotNet 0.15.8 покрывает открытие, последовательный `GetRecord`, чтение двух столбцов и чтение memo. Базовая серия на `efb9651` охватывает цели `net472` и `net8.0`. [Сценарии](../../dBASE.NET.Tests/benchmarks/Harbour/HarbourReadBenchmarks.cs), [базовые результаты](../benchmarks/efb9651/README.md)

1. **Подготовить входные данные и эталон.** Использовать 1 000 строк для проверки запуска и 10 000 строк для регулярных замеров. По мере добавления сценариев включать обычную и широкую схемы, DBF без memo и DBF с FPT. Для FPT включить пустые, короткие и многоблочные значения. DBT измерять отдельно при оптимизации его адаптера. На контрольных файлах сверить результаты `GetRecord`, `GetValue` и `IsDeleted` с Harbour, включая физический порядок записей, CP866, поля `@` и `=`, пустые значения и значимые пробелы в FPT. [Фикстуры и эталон](20261118-harbour-fastdbf.md)
2. **Зафиксировать базовый результат.** Собрать стенд в Release с целью `net472`. Записать фактическую версию .NET Framework, разрядность процесса, оборудование и размеры DBF/FPT. Для подтверждения работы именно на 4.7.2 нужен прогон на установленном рантайме 4.7.2. Цель `net472` сама по себе допускает запуск на более новом .NET Framework. В проекте библиотеки уже есть цель `net462`. [Цели проекта](../../dBASE.NET/dBASE.NET.csproj#L22), [версии .NET Framework](https://learn.microsoft.com/dotnet/framework/install/versions-and-dependencies)
3. **Раздельно измерить сценарии из таблицы ниже.** Использовать одни и те же входные файлы, поля, индексы и способ потребления результата. Сверять значения вне измеряемого участка. Сравнивать время, строки/с или запросы/с, выделенные байты на строку или запрос и количество сборок мусора. Для `Dbf.Read` полезно также измерять пиковую память. Прогреть JIT и отдельно фиксировать первое и повторное чтение файла. Первый проход в новом процессе может попасть в системный файловый кэш.
4. **После каждого этапа оптимизации повторять базовые сценарии.** Сначала проверить эквивалентность результатов, затем сравнить замеры с исходным и предыдущим вариантами. Это покажет вклад каждого этапа и возможную регрессию в точечном доступе.

| Сценарий | Базовый вариант и условия сравнения |
| --- | --- |
| Открытие | `FastDbf.ReadFile` до первого обращения к записи. Отдельно измерить DBF с FPT и без него. |
| Полный последовательный проход | Цикл `GetRecord` по физическим индексам. Сравнивать с пакетным чтением тех же полей и строк. `Dbf.Read` измерять отдельно как загрузку всей таблицы в память. |
| Последовательный проход по выбранным полям | `GetValue` для 1–3 столбцов на строку, особенно на широкой таблице. Пакетный вариант должен отдавать те же столбцы. Если сценарий фильтрует удалённые строки, включить `IsDeleted` в базовый замер. |
| Случайный доступ | `GetValue` и `GetRecord` на фиксированных последовательностях индексов. Проверить разреженную выборку и выборку с обращениями к соседним строкам. |
| Memo | На одном DBF/FPT измерить чтение выбранных полей без `M`, чтение части memo и чтение всех memo. Отдельно учитывать стоимость открытия и, для `Dbf.Read`, копирования FPT/DBT. |
| Декодирование в памяти | Декодировать заранее загруженные байты. Сравнить размещение полей в буфере и варианты декодеров независимо от файлового ввода-вывода. |

## Порядок оптимизаций на .NET Framework 4.7.2

1. **Убрать массивы и копирование на каждом поле.** Сейчас `DbfRecord` читает строку в массив и выделяет отдельный массив под каждое поле. На 10 000 строк × 50 полей это 510 000 выделений `byte[]` на этих двух уровнях. Передавать декодеру буфер, смещение и длину. Один раз вычислять смещения и выбирать декодеры по схеме, используя уже имеющиеся в `FastDbf` смещения. Задавать `List<object>` ёмкость по числу полей. У `MemoEncoder` есть зависимость от времени жизни массива указателя на блок. Он сохраняет исходные байты для последующей записи, поэтому такие байты должны принадлежать записи, если буфер чтения переиспользуется. [DbfRecord](../../dBASE.NET/DbfRecord.cs#L28), [смещения в FastDbf](../../dBASE.NET/FastDbf.cs), [MemoEncoder](../../dBASE.NET/Encoders/MemoEncoder.cs#L58)
2. **Читать последовательные записи блоками и декодировать выбранные столбцы.** `GetRecord` позиционирует поток на каждую запись, `GetValue` — на каждую ячейку. `Dbf.Read` проверяет конец данных через `PeekChar` до двух раз на запись. В .NET Framework `PeekChar` восстанавливает позицию потока, а `FileStream.Seek` обращается к Win32. Читать несколько записей в один переиспользуемый буфер и брать из него метку удаления и нужные поля. Порядок строк, `0x1A` и EOF обрабатывать на границах записей. Проверить короткое чтение потока, неполную последнюю запись и 64-битные файловые смещения. На разреженных выборках отдельно проверить точечный доступ с переиспользуемым буфером. [FastDbf](../../dBASE.NET/FastDbf.cs), [цикл Dbf.Read](../../dBASE.NET/Dbf.cs#L124), [BinaryReader.PeekChar](https://github.com/microsoft/referencesource/blob/main/mscorlib/system/io/binaryreader.cs#L102), [FileStream.Seek](https://github.com/microsoft/referencesource/blob/main/mscorlib/system/io/filestream.cs#L1485)
3. **Убрать промежуточные строки в декодерах.** Сначала попробовать разбор типовых `L` и `D` напрямую из байтов. Для `N` и `F` проверить `Utf8Parser` на ASCII-значениях с проверкой полного потребления поля. Для остальных представлений оставить текущий декодер. Сверить пустые поля, знак, экспоненту, округление и ошибки разбора. Для `C` проверить декодирование только полезного диапазона байтов, сохранив правила `Trim()` и пользовательских кодировок. Для бинарных полей сравнить `Unsafe.ReadUnaligned<T>` с `BitConverter` по смещению или `BinaryPrimitives` после проверки границ и с учётом порядка байтов. `System.Memory` с `ReadOnlySpan<byte>` и `Utf8Parser`, а также пакет `Unsafe` доступны для `net462`. [Числа](../../dBASE.NET/Encoders/NumericEncoder.cs#L50), [даты](../../dBASE.NET/Encoders/DateEncoder.cs#L28), [текст](../../dBASE.NET/Encoders/CharacterEncoder.cs#L43), [System.Memory](https://www.nuget.org/packages/System.Memory/4.6.3), [Unsafe](https://www.nuget.org/packages/System.Runtime.CompilerServices.Unsafe/6.1.2)
4. **Оптимизировать memo по отдельному профилю.** На проходе по выбранным столбцам читать содержимое только запрошенных memo. Для FPT убрать выделение и реверс массива под четырёхбайтовую длину, переиспользовать буфер содержимого и сохранить пробелы. Для DBT читать блоки за один проход с поиском пары `0x1A 0x1A`, включая случай на стыке блоков. Копирование всего memo в `Dbf.Read` обеспечивает редактирование после чтения. Для отдельного режима только чтения оценить доступ к исходному FPT/DBT по мере обращения. Если memo доминирует в базовом профиле, проверить этот этап сразу после блочного чтения. [Копирование memo](../../dBASE.NET/Dbf.cs#L115), [FPT](../../dBASE.NET/Memo/Adapters/FoxProAdapter.cs), [побайтовый поиск в DBT](../../dBASE.NET/Memo/Adapters/Dbase3Adapter.cs#L69)
5. **Сравнить `MemoryMappedFile` для частого случайного доступа.** Проверять на неизменяемом файле с теми же индексами, что и у буферизованного чтения, включая стоимость создания отображения. Открытие `FastDbf` с `readOnly: true` допускает запись другим процессом через `FileShare.ReadWrite`. При совместном доступе выбор буферизации зависит от требуемой видимости внешних изменений. [Открытие файла](../../dBASE.NET/FastDbf.cs#L33), [MemoryMappedFile](https://learn.microsoft.com/en-us/dotnet/api/system.io.memorymappedfiles.memorymappedfile?view=netframework-4.8.1)

Если после этих этапов в профиле преобладает создание объектов, измерить потоковую выдачу выбранных значений через типизированный API. Полный `DbfRecord` хранит `List<object>`, поэтому значения примитивных типов упаковываются при добавлении. Типизированный путь может убрать упаковку и создание объектов записей в сценариях импорта и агрегации. [Хранение записи](../../dBASE.NET/DbfRecord.cs#L54)

## Возможности современного .NET

| Возможность | Где проверить в dBASE.NET |
| --- | --- |
| `.NET 6+`, `RandomAccess.Read` и переработанный `FileStream` | Случайные и параллельные чтения DBF/FPT по явному смещению. `RandomAccess.Read` позволяет читать из одного дескриптора без общей позиции потока. Сравнить с буферизованным чтением Framework и с `MemoryMappedFile`. [Файловый ввод-вывод в .NET 6](https://devblogs.microsoft.com/dotnet/file-io-improvements-in-dotnet-6/) |
| `.NET 8+`, `double.TryParse(ReadOnlySpan<byte>, …)` | Разбор ASCII-полей `N` и `F` встроенными перегрузками с `NumberStyles` и `IFormatProvider`. Сравнить с `Utf8Parser` на Framework и сверить округление, переполнение и допустимые форматы. [Double.TryParse](https://learn.microsoft.com/en-us/dotnet/api/system.double.tryparse), [изменения числового парсинга](https://learn.microsoft.com/en-us/dotnet/core/compatibility/3.0#floating-point-formatting-and-parsing-behavior-changed) |
| `.NET Core 3.0+`, `System.Runtime.Intrinsics` | Управляемые SSE2/AVX2 для поиска терминатора в длинных DBT memo или обработки широких текстовых полей. Проверять после скалярного блочного варианта, если сканирование заметно в CPU-профиле. [Аппаратные интринсики .NET Core](https://devblogs.microsoft.com/dotnet/hardware-intrinsics-in-net-core/) |

При сравнении рантаймов сначала запустить одинаковый алгоритм на обоих. Затем отдельно включить новый API и повторить тот же замер. Так можно оценить вклад рантайма и вклад изменения кода.
