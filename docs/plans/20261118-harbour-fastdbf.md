# План чтения DBF Harbour через FastDbf

Дата плана: 18 ноября 2026 года.

Форк `dBASE.NET` ориентирован на быстрое чтение таблиц, созданных Harbour. Первый набор покрывает файлы `DBFCDX` версий `0x03` и `0xF5` и их FPT. Начинаем с воспроизводимых фикстур и сравнения с результатом чтения Harbour. Затем исправляем `FastDbf` и измеряем скорость. Поддержка индексов CDX и изменения записи Visual FoxPro вынесены за рамки этого плана. Работа начинается с текущей ветки форка. [Анализ изменений оригинала](20261118-upstream-changes-analysis.md)

## 1. Фикстуры

| Источник | Что берём |
| --- | --- |
| `HarbourDBF.NET/tests/generate-fixtures.prg`, `tests/fixtures/` | `basic.dbf` и `basic.fpt` как основу для полей `N/C/D/L/M`. Сохраняем случаи с обычным и пустым memo, добавляем кириллицу в `C` и `M`, memo со значимыми крайними пробелами, пустую дату и одну запись с меткой удаления через Harbour `DELETE`. Для многоблочного FPT проверяем переход через границу блока, например 56 и 57 байт текста при блоке 64 байта и 8 байтах служебных данных. |
| `HarbourDBF.NET/tests/generate-fixtures.prg` и `read-dbf/tests/timestamp-fixture.prg` | `special.dbf` с `+`, `=`, `^` и `@`. Сохраняем нативную генерацию автоинкремента, времени модификации и версии записи. Для `@` включаем пустое значение, 29 февраля, переход через полночь и значения с `.001`, `.123` и `.999` секунды. |
| `HarbourDBF.NET/tests/complex-fixture.prg` | Сценарии `numeric.dbf` и `wide.dbf`. Берём положительные, отрицательные и малые дроби в `N(15,2)` и `N(15,5)`, а также `9007199254740993` в `N(20,0)`. Последний пример фиксирует известную потерю точности при чтении через `double`. Решение о числовом типе публичного API принимается отдельно. |
| `read-dbf/MakeData/import-csv.prg`, `MakeData/generate-csv.js`, `tests/run.ps1` | Схема `test_main.dbf` + `test_main.fpt` с 13 полями. Берём профиль `direct` на 1 000 записей для контрольного прогона и сценарии с 0 и 1 записью для проверки границ. Фактический тип `CREATED_AT` в проверенном DBF — `@`, хотя в исходной схеме указан `T(8)`. Справочники городов и улиц пригодятся для сценариев чтения нескольких таблиц. |

Адаптируем генераторы в небольшие `.prg`, которые создают файлы в новом выходном каталоге. DBF и FPT записывает штатный Harbour RDD. Компактные файлы, ожидаемые значения и исходники генерации храним с тестами в `dBASE.NET.Tests/fixtures/harbour`. Для пересоздания фиксируем команды сборки `hbmk2`, версию Harbour и параметры генерации. Обычные .NET-тесты используют готовые файлы из репозитория.

## 2. Эталон чтения в Harbour

1. После генерации закрыть таблицу и открыть её отдельной Harbour-программой в режиме `READONLY` с `SET AUTOPEN OFF` и `SET DELETED OFF`. За основу взять `read-dbf/csharp/baseline/read-records.prg` и режим `values-only` из `read-dbf/csharp/special-types/capture.prg`.
2. Перебрать физические номера `1..LastRec()` через `dbGoTo(n)`. Для каждой записи выгрузить `RecNo()`, `Deleted()` и значения `FieldGet()`. В описании схемы сохранить фактические типы, ширину и точность по `dbStruct()` и физические байты типов дескрипторов DBF. В тестах `FastDbf` физическому номеру Harbour `n` соответствует индекс `n - 1`.
3. Сохранить результат в UTF-8 JSON. Даты выгружать через `DToS()`, timestamp через `hb_TToS()` с миллисекундами, текст и полное memo переводить в UTF-8. Числа, для которых важна точность, включая `N(20,0)`, записывать строками. Отдельно зафиксировать соглашения сравнения для пустых значений и заполнения пробелами у `C`. Для проверки блока memo сохранять его содержимое целиком, включая значимые пробелы.
4. Сохранить рядом версию Harbour, RDD, байт версии DBF, кодовую страницу и параметры генерации. В проверенных образцах `LDID = 0x00`, поэтому явно задаём `UA866` в Harbour и CP866 в `FastDbf`. Для `=` ожидаемое значение снимаем с конкретного DBF после повторного открытия. При регенерации обновляем эталон вместе с файлами, поскольку время модификации записей и дата заголовка зависят от запуска.

## 3. Исправления FastDbf после появления эталона

1. **Открытие только для чтения.** В `FastDbf.ReadFile(..., readOnly: true)` открывать DBF и FPT с `FileAccess.Read`. Провести режим через инициализацию `FastDbf` и `MemoContext`. Путь чтения FPT должен обходиться без `BinaryWriter` и без создания или исправления заголовка FPT. Проверить открытие по пути и через переданные потоки, доступные только для чтения. [Открытие FastDbf](../../dBASE.NET/FastDbf.cs#L31), [инициализация MemoContext](../../dBASE.NET/Memo/MemoContext.cs#L38)
2. **Подключение FPT по схеме DBF.** Сначала прочитать дескрипторы. Для таблицы Harbour без `M` игнорировать соседний одноимённый `.fpt`. Для таблицы с `M` подключать FPT и выдавать явную ошибку при его отсутствии. Проверить `special.dbf` с посторонним `.fpt` и `basic.dbf` с корректным, отсутствующим и недоступным для записи FPT. Сравнить пустой и многоблочный memo с эталоном, включая значимые пробелы при их наличии. [Инициализация FastDbf](../../dBASE.NET/FastDbf.cs#L60), [чтение блока FPT](../../dBASE.NET/Memo/Adapters/FoxProAdapter.cs#L49)
3. **Типы Harbour `@` и `=`.** `@` сейчас возвращается как `long`, декодер `=` отсутствует. Для целевого API запланировать `DateTime` без привязки к часовому поясу и `null` для пустого timestamp. Проверить точность до миллисекунд и совпадение результата в `GetValue` и `GetRecord`. Отдельно проверить `+` и `^` по эталону, включая значения, которые выставляет сам Harbour. Если исправление затрагивает общие декодеры, прогнать существующие тесты `Dbf`. [Текущий выбор декодеров](../../dBASE.NET/Encoders/EncoderFactory.cs#L11), [декодер даты и времени](../../dBASE.NET/Encoders/DateTimeEncoder.cs#L43)
4. **Физические записи и границы.** Проверить `RecordCount`, первую и последнюю записи, файлы с 0 и 1 записью и доступ к помеченной записи по физическому индексу. `IsDeleted` должен совпасть с `Deleted()` в эталоне. Для `GetRecord`, `IsDeleted` и `GetValue` добавить проверку отрицательных индексов до расчёта смещения. [Индексация FastDbf](../../dBASE.NET/FastDbf.cs#L88)

## 4. Замеры после проверок совместимости

Использовать 1 000 записей для проверки запуска и 10 000 записей с той же схемой для регулярных замеров. Генерировать DBF/FPT на 10 000 записей прямым циклом в Harbour с фиксированными параметрами. [Команды запуска и базовые результаты](../benchmarks/efb9651/README.md)

На одном файле отдельно измерять открытие, последовательное чтение через `GetRecord`, чтение выбранных столбцов через `GetValue` и чтение memo. Фиксировать параметры набора, время и аллокации. К оптимизациям переходить после сверки этих путей с эталоном Harbour.
